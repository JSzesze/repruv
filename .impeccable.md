## Design Context

### Users

People who need clean, portable Markdown from a public webpage or X post without creating an account. The core audience includes writers, researchers, developers, and people feeding web material into notes or AI workflows. They arrive with a URL and want a trustworthy result immediately.

### Brand Personality

Calm, precise, immediate. Repruv should feel like a well-made public utility: quietly confident, fast, and candid about caching and public URLs.

### Aesthetic Direction

Dark utility in a Firecrawl/Factory heat register: warm near-black surfaces, Hanken Grotesk + JetBrains Mono, and a single orange accent. No hero heading, full-page marketing blocks, or live activity feeds. A tiny upper-left REPRUV wordmark with one sharp orange status dot provides site identity. The initial view centers a compact URL input and submit control, backed by a localized matrix of crisp orange dots that pulse independently in opacity without bloom or blur. One restrained descriptive line clarifies supported sources and links to deeper guides. Below it, a small set of curated static example chips (not a recent-cache feed) teaches the product without privacy risk. A mono trust line may note free / anonymous / public / shared cache. Preserve crisp Retina rendering: text maintains readable contrast and icons are vectors rather than font glyphs. The input uses warm-black surfaces, a clear but restrained border, and a muted arrow that becomes orange through interaction. Orange is the sole secondary color and stays restrained to the brand dot, chips, focus, submit control, badges, and quiet interaction states. Results reveal only the document title, a `.md` badge, cache/word metadata, copy/download actions, and Markdown. Supporting guide pages may use concise, visible prose and examples, but avoid marketing fluff, dashboards, repetitive feature grids, API promotion, cards, or ornamental imagery. The primary experience should work equally well on desktop and mobile with strong keyboard and focus behavior. Respect reduced-motion with a static dot field.

### Design Principles

1. The URL is the only required input; make the path from paste to Markdown feel instantaneous.
2. Make system state legible but quiet: processing, cached, copied, and failed should never compete with the content.
3. Earn every element. If it does not help users convert, inspect, copy, or download, remove it.
4. Use proportion, hairlines, and typography for polish; decoration stays confined to the input module.
5. Keep the public-service contract visible: free, anonymous, cached, and intended only for public URLs.
